# How Loom Letter works

Loom Letter has three parts:

1. **Title templates**: Fusion macros (`.setting` files) that Resolve lists under
   Effects Library > Titles.
2. **The panel**: one Lua script, run from Workspace > Scripts. It uses the Resolve API to
   place titles and to build cut transitions, and UIManager for the window.
3. **Tooling**: a generator for the templates, a validator that simulates them, and a test
   suite that runs the panel against mock Resolve objects.

## Titles

### The timing rig

Every title template has the same hidden helpers on its main Text+ node (`Title`, or
`NameText` in the lower third):

| Control | Meaning |
| --- | --- |
| `InFrames`, `OutFrames` | Intro/outro length in frames. Shown in the Inspector. |
| `RevealIn` | 0 → 1 over the first `InFrames` frames |
| `RevealOut` | 1 → 0 over the last `OutFrames` frames |
| `EaseIn`, `EaseOut` | cubic ease-out of the two reveals (snappy arrival, accelerating exit) |
| `Ease` | `min(EaseIn, EaseOut)`: overall visibility |

Both reveals are expressions based on `comp.RenderStart` and `comp.RenderEnd`, which is the
title clip's range on the Edit page. That's why the outro moves when you trim a title. Setting
a length to 0 means "fully visible from the first (or until the last) frame", with no divide
by zero.

The look of each preset comes from what reads those values:

- **Slide Up**: a Transform's `Center` moves up into place and keeps moving up on the way out.
- **Blur In**: a Blur's size and a Transform's scale shrink to 0 and 1 as `Ease` reaches 1.
- **Pop**: an `easeOutBack` curve (overshoot) on `RevealIn`/`RevealOut` drives scale.
- **Tracking**: Text+ `CharacterSpacing` goes from `Tracking + Spread` down to `Tracking`.
- **Typewriter**: a Lua expression on `StyledText` reveals the `Message` control one UTF-8
  character at a time, at `Speed` characters per frame, with a blinking cursor.
- **Lower Third**: a rectangle mask grows the accent bar. The name and role slide out from
  behind it; a second mask hides everything left of the bar.

Each preset ends in a Merge over a transparent Background, so the title has proper alpha.
Everything the Inspector shows is an `InstanceInput` on the macro.

Templates are generated by `tools/build_templates.py`, so all presets share this rig.
`tools/validate_settings.lua` loads each file with stub Fusion constructors, checks every
connection and expression reference, and evaluates the expressions over a 120-frame clip. It
fails if a title is visible on its first or last frame.

### Placing a title without rippling

`Timeline:InsertFusionTitleIntoTimeline()` does an **insert** edit at the playhead, which
ripples everything after it. So Loom Letter never calls it on your timeline. Instead:

1. It keeps a **Loom Letter Scratch** timeline in a **Loom Letter** bin. The first time a
   preset is used, Loom Letter makes that timeline current, calls
   `InsertFusionTitleIntoTimeline` there, and switches back.
2. It asks that scratch title for its media pool item (`TimelineItem:GetMediaPoolItem()`).
3. It picks a track: the first unlocked, enabled video track above everything that overlaps
   the new title's time range, adding a track if none is free.
4. It places the title with `MediaPool:AppendToTimeline({{ mediaPoolItem, startFrame, endFrame,
   trackIndex, recordFrame }})`, which puts it at an exact frame and track and never ripples.
5. It sets the panel's values (text, font, style, colors, timing) through the placed clip's
   Fusion comp (`GetFusionCompByIndex(1)` → `FindTool` → `SetInput`).

Fallbacks:

- If a clip named exactly like the template (for example `LL Slide Up`) is in the
  **Loom Letter** bin, that clip is used as the source. This is a manual override in case a
  Resolve update changes step 2.
- If the title has no media pool item, Loom Letter customizes a fresh scratch copy, wraps it
  with `Timeline:CreateCompoundClip()`, and places the compound clip. **Decompose in Place**
  turns it back into a normal title.
- If Resolve won't place a title longer than the template's own length, Loom Letter retries at
  that length. You can drag the end to extend it.

## Cut transitions

For a cut between clip **A** (outgoing) and clip **B** (incoming):

1. Loom Letter finds or creates each clip's Fusion comp (`GetFusionCompByIndex(1)` or
   `AddFusionComp()`).
2. It inserts a short node chain directly in front of `MediaOut`: at the end of A (`LL_Out_…`)
   and at the start of B (`LL_In_…`).
3. The animated values are expressions. The ramp is

   ```
   out side:  k = clamp((time - comp.RenderEnd + N) / N)     1 on A's last frame
   in side:   k = clamp((comp.RenderStart + N - time) / N)   1 on B's first frame
   ```

   It's eased with `k³` for motion styles (fastest at the cut) or smoothstep for Flash and Blur.
   Because the ramp is relative to the clip's render range, it follows trims and needs no
   handles.
4. Styles are chosen so the motion continues through the cut. For example, Zoom In scales A
   from 1× to 2× and B from 0.5× to 1×, and Whip Pan moves both frames the same way. Motion
   styles use a Transform with **Mirror** edges and motion blur.
5. Each node is tagged with `tool:SetData("LoomLetter", { side, style, frames, version })`.
   Re-applying removes that side's tagged nodes first. **Remove** deletes all tagged nodes
   and reconnects whatever fed them to whatever they fed.
6. `N` is clamped to half the clip's length, so a short clip can hold both an In and an Out
   ramp without overlap.

Each comp edit is wrapped in `comp:Lock()` / `StartUndo()`, with `EndUndo()` always called
(an error between those two hangs Fusion). If something fails partway, the chain is rolled
back.

## The panel (UIManager)

- It's one self-contained Lua file. Loading it with `LOOMLETTER_TEST = true` returns the
  module instead of opening the window; the tests rely on this.
- Option pages sit in a `ui:Stack`. Switching pages only changes `CurrentIndex`, because
  showing/hiding widgets or changing geometry inside UIManager signals can deadlock Qt.
- Every button handler runs inside `xpcall`. Expected problems (no timeline, no cut near the
  playhead) show up as plain messages in the status line. Anything unexpected is written to
  the log with a stack trace.
- Panel settings are remembered between sessions with `fu:SetData("LoomLetter.Prefs")`.

## Assumptions to confirm in real Resolve

This build was written against the Resolve 21 scripting reference without a Resolve machine.
**Diagnostics** checks each assumption:

| Assumption | If it's wrong |
| --- | --- |
| `InsertFusionTitleIntoTimeline("LL Slide Up")` finds templates in the `Loom Letter` subfolder | Move the `.setting` files up into `Templates/Edit/Titles` |
| A title's internal tools can be found with `comp:FindTool("Title")` | Customization falls back to searching `GetToolList` by name |
| Title comps report the clip range as `COMPN_RenderStart..RenderEnd` | Animation timing would be off; the report shows the actual range |
| `GetMediaPoolItem()` works for titles | Titles are placed as compound clips (still no ripple) |
| `AppendToTimeline` honors `trackIndex` and `recordFrame` | Titles could land in the wrong place; the report shows where |
| Clip comps' render range matches the clip's trimmed range | Transitions would start/end on the wrong frames |
| `Timeline:GetSelectedClips()` exists | "Apply to selection" is unavailable; use the playhead |

## Known limitations

- The scripting API can't create real Resolve transitions or adjustment clips. Loom Letter's
  transitions are per-clip Fusion effects (see above).
- If a clip has more than one Fusion comp, Loom Letter edits the first one.
- The Typewriter speed is in characters per frame, so it types faster at higher frame rates.
- Previews are illustrations, not renders.
